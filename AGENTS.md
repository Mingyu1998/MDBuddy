# AGENTS.md

Instructions for AI coding agents (Codex, Claude Code, Gemini CLI, Cursor, Copilot, Jules, ...)
working in this repository. Humans: see README.md.

## If you were asked to build a simulation system

Follow `skills/mdbuddy/SKILL.md` (the same skill is mirrored at `.agents/skills/mdbuddy/` for agents
that load skills from there). In short: `mdbuddy doctor` → agree the decisions with the user → write
and `mdbuddy validate` a spec → `mdbuddy build spec.yaml` → explain each stage's output → report.
Never hand-edit build outputs; change the spec and rebuild. Most commands take `--json`.
The same tools are available over MCP: `mdbuddy mcp` (setup: `docs/agents.md`).

## If you are developing MDBuddy

- `src/mdbuddy/`: the pipeline. Stages in `pipeline.py` (`STAGES`), one module per stage:
  `fetch`, `prepare` (clean + PDBFixer repair), `orient` (OPM/manual/hydrophobic/self-assembly start),
  `forcefields`, `martinize` (+ `cgprotein` for pre-coarse-grained `cg_proteins`), `membrane` (COBY,
  incl. the `coby:` passthrough; also the self-assembly soup), `assemble` (GROMACS folder,
  validation), `mdp`. Also `lipids` (names across Martini versions), `selfassembly` (analysis),
  `viewer` (HTML placement viewer), `mcp_server` (stdlib MCP server), `cli`.
- `skills/mdbuddy/`: the agent skill (SKILL.md + references), canonical copy. After editing it run
  `python tools/sync_skill.py` (mirrors it to `.agents/skills/mdbuddy`; a test checks they match).
  Keep it in sync with CLI flags and spec keys, and keep SKILL.md agent-neutral.
- The spec schema lives in `spec.py` (`DEFAULTS`, `_validate`). New keys need a default,
  validation, and an entry in `skills/mdbuddy/references/spec_reference.md`.
- Pinned force-field files: `forcefields.REGISTRY` / `LIPID_SETS`. Changing a URL means changing the
  commit hash *and* the SHA-256 together.
- Core package depends only on PyYAML; `orient`/`selfassembly` also need numpy (installed with
  COBY/vermouth), scipy is optional. vermouth, COBY and PDBFixer are run as external programs
  (`martinize2`, generated `coby_build.py` / `repair_pdbfixer.py`), never imported, so every step
  can be replayed by hand.
- Lipid names: `src/mdbuddy/data/lipids.json` is generated by `tools/build_lipid_db.py` from the M3
  lipidome naming spreadsheet, the itps and COBY's definitions. Never hand-edit it; add corrections to
  `CURATED_*` in the script (with the reason), regenerate, then run
  `mdbuddy lipids report docs/lipid_name_changes.md` (a test fails if the document is stale).
- Orientation benchmark: `tools/benchmark_orientation.py` (needs network to OPM); results are quoted
  in `skills/mdbuddy/references/orientation.md` - update them if the scoring changes.
- Tests: `pytest`. `tests/conftest.py` provides fake martinize2/COBY/force-field files; keep the real
  tools out of the unit tests (they must pass with only PyYAML, numpy and pytest installed).
