# Lipid names across Martini versions

Martini lipid names are four-letter codes for the **tails + head group**. The convention
changed with the Martini 3 lipidome (Pedersen et al., *ACS Cent. Sci.* 2025,
doi:10.1021/acscentsci.5c00755). The same name can now mean a different molecule, and the
same molecule can have a different name. **Always match lipids by chemistry, never by name.**

MDBuddy knows three lipid sets (`src/mdbuddy/data/lipids.json`, generated by
`tools/build_lipid_db.py`):

| Set | Used when | Source |
|---|---|---|
| `martini2` | `forcefield: martini22` / `elnedyn22` | Martini 2 naming table (lipidome repo) + pinned M2 itps |
| `martini3_lipidome` | `forcefield: martini3` (default) | [M3-Lipid-Parameters](https://github.com/Martini-Force-Field-Initiative/M3-Lipid-Parameters) @ `2121527`, its official naming table |
| `martini3_2021` | `forcefield: martini3` + `forcefield_files.martini3_lipids: release2021` | lipids shipped with the 2021 Martini 3 release (Martini 2 naming) |

## Commands

```bash
mdbuddy lipids show DLPC CDL2 POP2          # what each name means in every version
mdbuddy lipids convert CDL2 POP2 DIPC --from m2 --to m3   # best match first, flags charge changes
mdbuddy lipids search cardiolipin --ff m3
```

## Names that changed or clash (from the official naming table)

| Molecule | Martini 2 / M3 2021 | M3 lipidome | Watch out |
|---|---|---|---|
| di-C12:0 PC (dilauroyl) | DLPC (3-bead tails, C12–C14) | **DUPC** | lipidome **DLPC is dilinoleoyl (di-C18:2)** |
| di-C14:0 PC (dimyristoyl) | DLPC | **DMPC** | |
| di-C18:2 PC (dilinoleoyl) | DIPC | **DLPC** | |
| di-C16:0 PC | DPPC (covers C16–C18) | DPPC | lipidome adds DSPC (di-C18:0) and PSPC (16:0/18:0) |
| C16:0/18:2 PC | PIPC | **PLPC** | lipidome **PIPC is C16:0/20:2** |
| C18:0/22:6 PC | PUPC (C16:0/22:6) | SDPC | |
| C18:0/20:4 PC | PAPC (C16:0/20:4) | PAPC or SAPC | |
| Cardiolipin | CDL0 (0), CDL1 (1−), CDL2 (2−); four 5-bead tails | **TOCL** (tetraoleoyl), TMCL (tetramyristoyl), **always 2−** | CDL0/CDL1 → TOCL changes the charge |
| PI(4,5)P2 | POP2 (generic PIP2, ring positions not encoded) | **POP6** | lipidome **POP2 is PI(3,4)P2** |
| PI(4)P | POP1 (generic PIP) | POP4 | lipidome POP1 is PI(3)P, POP5 is PI(5)P |
| PI(3,4,5)P3 | POP3 | POP3 | |
| Sphingomyelin d18:1/16:0 | DPSM | PSM | |
| Cholesterol | CHOL (M2 model) | CHOL (v1.0, Borges-Araújo 2023) | same name, different model |

The same pattern holds for the other head groups (PE, PS, PG, PA). Check with `mdbuddy lipids show`.
The official table maps several lipidome lipids to one Martini 2 name, because Martini 2's 4:1
mapping does not tell C16 from C18. `convert` lists them all, best chemical match first.

Corrections MDBuddy makes to the official table (documented in `tools/build_lipid_db.py`):
- **PIPs:** the table copies M3 names into the "Martini 2 name" column (it lists M2 POP4–POP7,
  which do not exist). MDBuddy maps by phosphorylation level instead. M2 POP2 → POP6 is an
  assumption, because the M2 itp does not encode ring positions. Confirm it against the study you are reproducing.
- **Cardiolipin and cholesterol** are not in the table and were added from the itp headers.

## What COBY can build (COBY 1.0.15)

COBY places lipids from its own bead libraries: `LTF` for the lipidome, `default` for the 2021
release and cholesterol, `M2` for Martini 2. MDBuddy picks the library per lipid
(`lipid:POPC:7:params:LTF lipid:CHOL:3:params:default`). Each COBY bead list was compared with
the itp it has to match:

| Set | Exact | Fixed by MDBuddy (name-only typos) | Cannot be built |
|---|---|---|---|
| lipidome | 268 | TOCL, TMCL, DODG | 11 (bead count/order differs: DX*, CSM, CCER, DPLC, DPLE, DO2B, DO3B) + 400 with no COBY definition (ether lipids, plasmalogens, DOTAP) |
| 2021 release | 73 | 40 (`C5A`/`T1B` naming on 5-bead tails) | 0 |
| Martini 2 | 2 checked (POPE, POPG) | – | no COBY definition for cardiolipin, cholesterol, PI/PIPs, SM, ceramides, lyso and glycerides |

"Fixed" means COBY places the right bead at the right position but gives it the wrong name.
For example, COBY's `TOCL` has `C2A1` and `C3C2` where the itp has `D2A1` and `C3B2`. After COBY runs,
MDBuddy renames exactly those atoms, and only when they carry the known wrong name. It
reports the count in the build log. The atom-by-atom validation afterwards still checks every
molecule.

## Rules for the agent

1. When the user gives lipid names, find out where they come from: a Martini 2 paper, CHARMM-GUI,
   or chemistry ("POPC with 30% cholesterol"). If they come from another Martini version, run `mdbuddy lipids convert`
   and show the user the chemistry before writing the spec.
2. Never translate a name silently. Say "M2 CDL2 (2−) → M3 TOCL (2−)" or
   "M2 CDL0 is neutral, M3 TOCL is 2−. The charge changes and ions will be added".
3. If `mdbuddy build` prints `LIPID NOTE ... means a different molecule`, tell the user which
   molecule they are getting.
4. If a lipid cannot be built by COBY, say so and suggest the closest buildable lipid (same head group
   and similar tails). Never edit COBY output by hand.
